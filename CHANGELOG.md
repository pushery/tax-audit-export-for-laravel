# Changelog

All notable changes to `pushery/tax-audit-export-for-laravel` are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/), and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

A release carries only the sections that have an entry, in this order: `### ⚠️ Breaking`, `### ✨ Added`, `### 🔧 Changed`, `### ⚡ Performance`, `### 🐛 Fixed`, `### 🔒 Security`, `### 🧹 Deprecated`, `### 🗑️ Removed` and `### 📚 Documentation`.

## [0.1.0] - 2026-11-20

### ✨ Added

- **An export for a tax audit after the description standard of the GoBD.** `Export` writes a CSV file for each table, the `index.xml` that describes them and the document type definition `gdpdu-01-09-2004.dtd` into a directory of its own. The definition ships byte for byte as the BZSt publishes it in the package of the DSFinV-K 2.4. Each record is written as it arrives, so a table may come from a source that loads it in chunks and yields arrays, such as a query's `lazyById()` with each row mapped to the columns of the table. A query's `cursor()` is none, since it yields objects and the database driver buffers its whole result. A directory that holds an export already, a directory or a file the export cannot create or write, and a file a full disk or an exhausted quota stops partway are refused with an `UnwritableExport`, an exception of its own beside the reader's `UnreadableExport`. An export that stops partway, at a refused value, a failed write or an exception of its rows, removes the files and directories it created, so the next attempt can write into the same directory.
- **Tables and columns as values.** `Table` names its file, its columns in the order of the header line, the first as its key unless the table is built with `keyed: false`, as the tables of the DSFinV-K are, and the tables whose keys it carries. `Column::text()` takes a greatest length, `Column::numeric()` the number of decimals. A definition the description cannot carry, such as a column twice, a reference to a table that is not exported or has no key, or a table written to `index.xml` or to the file of the definition, is refused before the first file is written. File names are compared without the case of their letters. A file name holds ASCII letters, digits, points, hyphens and underscores and begins with a letter or a digit, so one with a path, an umlaut or a line break is refused. A column name that is a whole number, such as `2024`, is refused, since PHP keeps it as an integer when it keys a row.
- **Every value held to its column.** A number has no more decimals than the accuracy of its column, and a column without one holds whole numbers. A number given as a string with a line break, at its end as well, is refused, since a line feed in the file ends the record. A text is no longer than the greatest length of its column, counted in characters. A value its column cannot hold is refused with an `InvalidDefinition` that names the column. A text keeps its first character, so the files are read through an import that follows the `index.xml` and never opened directly in a spreadsheet, which takes a text that begins with `=`, `+`, `-` or `@` for a formula.
- **A reader that goes through the `index.xml` alone.** `Reader` takes the tables, their columns and types, and the delimiters, the first record and the encoding of each file from the description, holds the `index.xml` it parses and the longest record it takes, counted without its line end, to a limit each, and reads a table written in `UTF8` or in `ANSI`, refusing any other encoding even where the configured list names it. A table is read by its name, so a description that names two tables alike is refused when the reader opens it. An `index.xml` the reader cannot read, such as an empty one or one that names a column delimiter of two bytes, a record delimiter other than a line feed or a carriage return and a line feed, or a table the export would refuse to write, is refused with an `UnreadableExport`.
- **A validator for test suites.** `Testing\IndexValidator` checks an `index.xml` against the definition and returns a message for every place it departs from it.
- **Settings for the data supplier and the reader.** `ExportSettings` reads the supplier and the limits of the reader from `config/tax-audit-export.php` and starts an export or a reader with them. It reads them once in each request or queued job, so under Octane and in a long-running queue worker a supplier set for one request or job is the one its export names. A supplier name left empty, such as `TAX_AUDIT_EXPORT_SUPPLIER_NAME=` with nothing after it, names the application, the value of `app.name`.
